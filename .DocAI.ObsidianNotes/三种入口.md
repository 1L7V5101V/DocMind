看代码就清楚了——三个入口最终都调**同一个方法** `agentExecutionService.execute(request)`：

| 入口 | 代码 | 底层 |
|---|---|---|
| `/chat` (ChatReactAgent) | `agentExecutionService.execute(request)` ← 带 `conversationId` | 同一套 |
| `/execute` (PlanExecuteAgent) | `agentExecutionService.execute(request)` ← 不带 `conversationId` | 同一套 |
| `/plan/execute` (旧兼容) | `agentExecutionService.execute(request)` ← 纯 `task` | 同一套 |

所以"底层都需要同一套工具注册、参数校验、上下文维护、权限判断、结果汇总"说的就是这个**共用关系**：

```
AgentExecutionService.execute()
    ├── 工具注册 → AgentToolRegistry（所有入口共享）
    ├── 参数校验 → validateToolParameters()（所有入口共享）
    ├── 上下文维护 → ContextManager（所有入口共享）
    ├── 权限判断 → InternalService.checkPermission()（所有入口共享）
    ├── 审批 → AgentApprovalService（所有入口共享）
    ├── 执行 → dispatchTool()（所有入口共享）
    └── 结果汇总 → 最终合成回答（所有入口共享）
```

**区别只是入口参数不同**：`/chat` 多传了一个 `conversationId` 用于关联对话历史，`/execute` 和 `/plan/execute` 不传。实际走到执行器里，流程完全一样。如果拆成两套独立的类，这七块逻辑就要复制一份，改一个 bug 得改两处，这就是文档里说的"重复代码和入口能力不一致"。
