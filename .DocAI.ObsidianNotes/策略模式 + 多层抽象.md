结合你的代码，拆开解释：

### 策略模式（一个接口，两种配置可以切换）

就是一个接口，多种实现，**运行时根据配置选择用哪个**：

```
FileService（接口）
  ↑           ↑
  │   策略模式判断配置
  │           │
本地存储策略          MinIO 存储策略
（写磁盘文件）          （写对象存储）
```

在你代码里体现在 `FileServiceImpl.upload()` 第 64 行：

```java
if ("local".equals(fileStorageConfig.getStorageType())) {
    // 本地存储 → 写磁盘文件
} else if ("minio".equals(fileStorageConfig.getStorageType())) {
    // MinIO 存储 → 写对象存储
}
```

改配置就切换，不改代码，这叫**策略模式**。

### 多层抽象

```
Controller（请求入口）
    ↓
FileService（接口抽象，定义 upload/download/delete 等操作）
    ↓
FileServiceImpl（核心逻辑，校验、分片、权限判断）
    ↓
本地文件系统 / MinIO 客户端（实际存数据的地方）
```

每一层只管自己的事：
- **Controller** — 收请求、返响应
- **FileService 接口** — 定义"能干什么"，调用方不关心底层实现
- **FileServiceImpl** — 策略分发、业务逻辑（分片合并、元数据存库）
- **存储后端** — 真正读写文件，可以随时替换

### 一句话

> **策略模式** = 同个接口不同的干活方式（存本地 vs 存 MinIO），配置文件选哪个
> **多层抽象** = 各层职责分离，替换一层不影响其他层
