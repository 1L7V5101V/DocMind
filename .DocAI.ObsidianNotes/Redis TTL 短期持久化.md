在项目设计中，**"Redis TTL 短期持久化"** 是指：

**不用数据库永久存储**，而是利用 Redis 的 **TTL（过期时间）** 机制，让数据存活一段时间后自动淘汰。具体策略：

| 数据 | TTL | 说明 |
|------|-----|------|
| 对话消息 (`conv:`) | **24h** | 每次发消息刷新过期时间 |
| Agent 上下文 (`ctx:`) | **无 TTL** | 随对话删除而清理 |
| Agent 任务快照 (`agent:task:`) | **7天** | 执行快照，用于断点续跑/查看 |
| 知识索引任务 (`agent:knowledge:job:`) | **7天** | 索引状态跟踪 |
| 审批令牌 (`agent:approval:`) | **300s** | 临时审批 |

核心思想在 `03AI Agent设计.md:164` 有说明：
> 并非永久记忆库，采用 Redis TTL 短期持久化：对话 24h，Agent 任务快照 7 天，知识索引任务 7 天

这样做的理由（见同文档第 177 行）：
- 会话和任务**更多服务于近期交互**，不需要永久存储
- **降低存储成本**，避免历史无限累积影响**隐私和性能**
- Redis AOF 持久化（`--appendonly yes`）保证重启不丢数据，兼顾了**快速访问**和**崩溃恢复**
