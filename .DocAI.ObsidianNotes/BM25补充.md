看代码（`KnowledgeBase.java:234-282`），BM25 的补充方式很直接：

```
hybridSearch() 执行流程：

① 向量检索
   query → Embedding API → 向量
   → HNSW 搜索 → 取 topK × 3 个候选（标记 source="vector"）

② BM25 检索
   遍历 Redis 中所有分段/文档内容
   → 对每个片段算 BM25 分数 → 取 topK × 3 个候选（标记 source="bm25"）

③ 合并去重
   vectorResults 先进结果集
   bm25Results 逐个追加 → 遇到已存在的 id 就跳过
   → 取最终 topK 返回
```

**关键逻辑：** BM25 找到的片段如果**向量检索已经找到了就跳过**，只补充向量没找到的那些。这补的是"语义不接近但关键词完全匹配"的情况。

比如用户搜 `FileUploadConfig`：
- **向量检索** — 可能召回到"文件上传设置"（语义相关但词不匹配），漏掉精确的类名
- **BM25** — 精确命中包含 `FileUploadConfig` 的片段，补充进结果集

之后如果启用了 Rerank，还会对合并后的候选集做二次排序。
