CSRF（跨站请求伪造）是指攻击者诱导用户访问恶意网站，利用用户**已登录目标网站的身份**，伪造请求发送到目标网站执行非法操作。

举个例子：

```
1. 用户登录了银行网站 bank.com，浏览器存了 Session Cookie
2. 用户没有登出，又访问了攻击者的网站 evil.com
3. evil.com 页面里有个隐藏表单，自动向 bank.com/transfer?to=攻击者&amount=10000 发起 POST 请求
4. 浏览器自动携带 bank.com 的 Cookie 发出请求
5. 银行服务器看到 Cookie 认为是用户本人操作，转账成功
```

**核心原理**：浏览器会自动携带目标域名的 Cookie，服务器无法区分这个请求是用户主动操作还是被伪造的。

**为什么文档说 API 服务禁用 CSRF 保护？**
因为前后端分离架构不使用 Cookie + Session 认证，而是使用 **Token（JWT）放在请求头中**。攻击者无法通过浏览器自动携带的方式带上自定义请求头的 Token，所以 CSRF 攻击基本不成立，CSRF 保护也就显得多余了。
